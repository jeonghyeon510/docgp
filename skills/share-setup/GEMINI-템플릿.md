# 프로젝트 규칙

여기 적은 내용은 에이전트가 **항상** 지킨다.
아래는 시작용 뼈대다. 필요 없는 줄은 지우고 이 프로젝트에 맞게 고쳐 쓴다.

같은 지시를 대화마다 반복하고 있다면, 그게 이 파일에 들어갈 내용이다.

## 응답 언어

항상 **한글로** 답한다. 사용자가 영어로 물어도 한글로 답한다.

## 작업 방식

- 파일을 덮어쓰기 전에 **반드시 먼저 읽는다.**
- 커밋은 **요청받았을 때만** 한다.
- 새 라이브러리나 프레임워크를 추가하기 전에 먼저 물어본다.
- API 키를 코드에 직접 적지 않는다. 환경변수를 쓴다.
- 기준 문서와 실제 구현이 어긋나 보이면, 임의로 맞추지 말고 **어긋난 지점을 알려준다.**

## 코드 결과물

- 만든 코드(`.html` · `.css` · `.js` 등)는 **`output/` 폴더 안에** 만든다. 프로젝트 루트에 만들지 않는다.
- 루트에 이런 파일이 이미 있으면 **먼저 `output/`으로 옮긴 뒤에** 작업을 시작한다. 옮겼다는 사실을 알린다.
- 파일끼리 참조할 때는 상대경로를 쓴다 (`href="style.css"`). 절대경로를 쓰지 않는다.
- 문서는 `output/`에 넣지 않는다. 코드 결과물만 들어간다.
